# Соты — рой агентов

Короткая справка для инженера и для агента: что именно делает рой, чего он не делает и почему.

## Зачем

Один агент читает последовательно: пока он на десятом листе, первые три он уже «помнит» приблизительно. Рой меняет
это не «умом», а **параллельностью с одинаковой рубрикой**: N агентов проверяют по своему куску, каждый обязан
ответить в одном формате (что проверил, что нашёл, где именно, чего нет), а сводка складывает ответы и **называет
расхождения**. Точность даёт не количество агентов, а рубрика и сведение.

## Где он нужен, а где нет

| Задача | Рой | Почему |
| --- | --- | --- |
| Сверка спецификации с чертежами/Э3 | да | куски независимы, проверка одинаковая, нужны ссылки на лист |
| Поиск по большому корпусу (тендеры, архив) | да | веер по источникам, дедупликация по предмету |
| Проверка 40 экранов/окон на одинаковые ошибки | да | одна рубрика на всех, каждая сота — своё окно |
| Написание программы ПЛК, рисование экранов | нет | общее состояние: агенты мешают друг другу |
| Правки в проекте | нет | рой работает только на чтение |

## Права

Соты — **настройка профиля** (`SYSAI → Доступы → «Соты — рой агентов»`): тумблер и число сот 4–40. Раздел входит в
подписанный документ доступов, поэтому число сот нельзя поднять на машине: окно получает предел из документа и не
даёт выбрать больше. Выключено — значка сот в окне нет вообще.

Рой работает **только на чтение**: задание прямо запрещает запись, а папки на запись ограничены доступами профиля.

## Как идёт

1. **План.** Планировщик делит задачу на независимые части (или берём явный список: файлы, механизмы, пункты ТЗ).
2. **Работа.** Каждая сота — своя сессия Hermes со своим куском; одновременно не больше шести (очередь у провайдера
   не делает быстрее).
3. **Ответ.** Строго один блок `<answer>{...}</answer>`: `checked`, `found[{key,value,where}]`, `missing[{key,why}]`.
4. **Сводка.** Ответы складываются механически: находки — таблицей со ссылками, «нет» — отдельным списком,
   **разные значения на одном ключе — «спорное»**, их не затирает последний ответ.
5. **Арбитр.** Короткий вывод (что подтвердилось, что открыто, что проверить первым). Если арбитр не ответил — отчёт
   всё равно есть, без вывода.

## Состояния соты

| Сота | Значение |
| --- | --- |
| тусклая | ещё не начинала |
| зелёная пульсирует | ищет |
| зелёная ровная | ответила |
| жёлтая | спор: её значение расходится с другой сотой |
| красная | ошибка (модель отказала, инструмент упал) |
| серая | не успела до конца срока — это не ошибка |

Срок роя — 5 минут по умолчанию; соты, не успевшие к сроку, помечаются «не успел», а не «ошибка»: иначе сорок
красных сот пугают и перестают что-либо значить.

## Что остаётся после

`<проект>/.sysai/swarm/<id>/`:

- `result.md` — отчёт: находки со ссылками, «нет», спорное, таблица сот;
- `state.json` — состояние роя и ответы машинно;
- `cell-NN.md` — что ответила каждая сота (её собственный след).

Отчёт открывается кнопкой «Открыть отчёт» в панели сот.

## Деньги

Рой — это N запросов к модели одновременно. Один запуск на 16 сот по 5 минут — это заметные деньги, поэтому:
число сот ограничено профилем, срок ограничен, а запуск идёт только по явной кнопке (никогда сам).
