# I. Что уже есть в SYSAI для этапов S3–S7 «Смет»

Дата: 2026-11-22. Этап 2 задачи «Смета СМР Про, MSP по законодательству РБ, доступы, ИИ-сотрудник и A2A»
(этапы S1–S7 в [TASKBAR.md](../../../../TASKBAR.md)). Проверено по коду ветки на `f464ee1`, не по документации:
каждая ссылка `файл:строка` прочитана. Цель — не делать заново то, что готово.

Коротко: дерево компании, лимиты расходов агентов, «в сети», роль «Проверяющий» в Telegram и рой агентов на одном
ПК уже есть. Нет: ролей панели кроме «пользователь / суперпользователь», начальника отдела как роли, лимита на
человека, подтверждения доступа руководителем, связи агент–агент, выдачи агента из дерева при входе, ничего
сметного.

## Дерево

**Есть**
- Дерево компании для карты «Подразделения»: каждый сотрудник и отдел ровно один раз, родитель по приоритету связей,
  петли разрываются по слабейшей связи — `app/org_tree.py:1-20`, `build()` на `app/org_tree.py:31`.
- Строится на странице `/departments` — `app/main.py:4076`, вызов `org_tree.build` на `app/main.py:4203`.
- Данные: отделы `Department` — `app/db.py:188`; членство с должностью и признаком «основной» `EmployeeDepartment` —
  `app/db.py:207`; связи «подчиняется», связи блоков `OrgRelation` — `app/db.py:223`.
- Агент сети привязан к человеку и отделу: `NetAgent.user_id`, `employee_id`, `department_id` — `app/net/models.py:13-15`.

**Нет**
- Узлов «смета», «чертёж», «объект» в дереве: оно знает только компанию, отделы и людей. → S4.
- Начальника отдела как поля: отдел «начальнику» ищется как первый активный основной член отдела с Telegram
  (`_head_of`, `app/doc_intake.py:430-435`). → S4/S5.

## Роли

**Есть**
- Панель: две роли — `user | superuser` (`app/db.py:120`, `app/accounts.py:31`). Суперпользователь из
  `ADMIN_USERNAME` создаётся при каждом старте (`ensure_superuser`, `app/accounts.py:194`), последнего
  суперпользователя нельзя понизить (`app/accounts.py:248-251`).
- Telegram (ИИ-сотрудник): уровни `employee` «Сотрудник», `full` «Полный доступ», `reviewer` «Проверяющий»,
  `observer` «Наблюдатель», плюс старый `director` «Директор» — `app/access.py:14-16`, порядок проверки
  `app/access.py:46-55`. Уровень ставится в карточке сотрудника (`app/main.py:3767-3774`). Плашка «проверяющий» из
  S5 уже есть здесь.
- Сеть агентов: встроенные профили доступов «Инженер ОПО», «Руководитель ОПО», «ТО», «Наблюдатель» —
  `app/net/access.py:180-185`; у руководителя проекты отдела и больший бюджет — `app/net/access.py:125-127`.
  Агент простого пользователя начинает «Наблюдателем», доступы даёт суперпользователь — `app/net/routes.py:211-213`.

**Нет**
- Ролей панели «начальник отдела», «админ», «директор» и «обслуга сервиса»: в панели всё решает
  `me["role"] == "superuser"` (например `app/net/routes.py:162`, `app/net/routes.py:206`, `app/net/routes.py:299`). → S5.
- Единой модели: три независимых набора (роль панели, уровень Telegram, профиль агента) не связаны друг с другом. → S5.

## Сметы

**Есть**
- Разбор входящих документов ИИ-сотрудником знает тип «смета» (номер, дата, суммы, строки) — `app/doc_intake.py`,

- Word по шаблону на сервере: `app/doc_templates.py` — шаблон .docx компании с полями `{{Дата}}`, поля заполняются

  выходных форм РБ (S3): объект, заказчик, дата, суммы; строк таблицы он не делает (см. «Нет»).
- Word по образцу на ПК агента: `hub/seed/doc-kit` — собирает .docx из Markdown в оформлении образца (руководства,
  паспорта); таблицы собирает из Markdown (`hub/seed/doc-kit/docxout.py:329`), но не в сетку готовой формы.

**Нет**

  значения `{{Поле}}` в готовый DOCX и не повторяет строку шаблона, а локальная смета, С-2а и С-3а —
  таблицы позиций с любым числом строк. Строки таблиц (и вывод в Excel) для S3 нужно сделать. → S3.
- Базы НРР, индексов МАиС, текущих цен, расчёта сметы, импорта CiC. → S3 (что повторить — `docs/opo/plan-2026-11/research/H-smr-pro.md`).
