# Haiwell Happy: программа для контроллера, а не `.gpc`

Haiwell — отдельная среда программирования контроллеров, и её проект нельзя мешать с Machine Expert: другой
вендор, другой формат, другой язык (у Haiwell LD — релейные схемы). Поэтому это отдельный инструмент, а не набор
команд внутри `plc-kit`.

## Что этот инструмент делает

Программу контроллера Haiwell — целиком, из спецификации проекта:

| Инструмент | Что делает |
|---|---|
| `hawell_program` | собирает программу из `project.spec.json` и показывает: схемы списком инструкций, таблицу сигналов и адресов, замечания. Ничего не пишет — посмотреть и согласовать. |
| `hawell_export` | пишет папку `hawell/` рядом с проектом: `program.il` (список инструкций), `program.ld.txt` (та же схема лестницей), `io.csv` (сигнал → адрес), `README.txt` (шаги в Haiwell Happy). |
| `hawell_read` | читает записанное обратно: адреса из `io.csv`, проверка «один адрес — один сигнал», только известные инструкции в `program.il`. |
| `hawell_info` | что за файл `.gpc`: заголовок, размер, энтропия тела. `decoded: false` — состояние формата, не ошибка. |
| `hawell_check` | то же плюс находки: нет заголовка, огрызок, состояние разбора. |

Адреса — Haiwell: **X** входы, **Y** выходы, **M** внутренние реле, **T** таймеры, **C** счётчики, **D**
регистры; номера десятичные. Выдаются детерминированно (по порядку механизмов в спецификации), поэтому повторный
экспорт того же проекта даёт тот же файл — его видно в диффе.

Схема на механизм: пуск (`LD`), самоблокировка выходом (`OR`), стоп и аварии — размыкающими (`ANI`), выход
(`OUT`); задержка пуска — `TON` с регистром `D` (0,1 с на единицу); авария — защёлка на `M` со сбросом, если в
спецификации заведён вход `reset`.

## Почему не `.gpc`

Проверено на настоящем проекте (`600_S1_Благовещенск_01A1_071223.gpc`, 51 942 байта) и на двух его версиях:

| Проверка | Результат |
|---|---|
| Заголовок | `b0 b0` + строка `HaiWell`, дальше двоичный заголовок — читается |
| zlib / lzma / bz2 / zstd | ни один не распаковывает тело |
| XOR с ключом постоянной длины | не снимается: доля нулей после XOR со сдвигом не отличается от исходной |
| Энтропия тела | 7,06 бит на байт — плотные данные |
| Общие блоки у двух версий одного проекта | только нули — то есть тело пересчитывается целиком |

Это закрытое сжатие (или потоковый шифр) вендора. Писать `.gpc` — значит иметь их кодировщик; выдавать
«похожий» файл нельзя: Haiwell откроет его как пустой проект, а инженер узнает об этом на объекте.

## Экспорт программы (`.hwb`) — тоже закрытый

Среда умеет File → Export (программа / таблица / комментарии компонентов) и File → Import. Соблазн понятный:
«экспорт — это обмен, значит можно отдать файл, который инженер просто импортирует». Проверено на реальном
экспорте программы (`1.hwb`, 4 302 байта, метка `HWFBD`):

| Проверка | Результат |
|---|---|
| Заголовок | `b0 b0`, размер файла (`0x10ce` = 4 302), метка `HWFBD`, дальше числа переменной длины |
| Читаемое | только шапка — имена разделов в UTF-16 (например «Входы» с 0x1d) |
| zlib / raw deflate / gzip / bz2 / lzma, в т.ч. со сдвигов 0…0x60 | не распаковывается ни один |
| Энтропия тела (с 0x2c) | 7,05 бит на байт, нулей 8 % |

Тот же закрытый контейнер, что и `.gpc`, только на блок программы. **Писать `.hwb` нельзя**: импорт
«похожего» файла среда либо отвергнет, либо примет пустым проектом.

Практический вывод: у Haiwell нет файла, который мы можем собрать и который сразу грузится в контроллер.
Программа передаётся списком инструкций; если диалог File → Import принимает текстовый тип, `program.il`
подаётся туда напрямую — это уточняется у владельца (список типов в окне импорта).

Поэтому путь такой: **программа отдаётся списком инструкций** — это штатный язык Haiwell Happy (в руководстве у
каждой инструкции в графе «Support language» стоят LD, FBD и IL; LD ↔ STL переключается по F7), плюс лестница
для сборки руками и таблица адресов для таблицы символов. Последние два действия — в самой программе: вставить,
скомпилировать (F9), сохранить `.gpc`.

## Когда применять

- «Сделай программу для Haiwell» → `hawell_program`, показать инженеру, потом `hawell_export`.
- «Что за файл `.gpc`, наш ли это проект» → `hawell_info` / `hawell_check`.
- «Почему не сохранил проект Haiwell» → `.gpc` пишет только Haiwell Happy; в `README.txt` из экспорта шаги.
- «Проверь, что экспорт не поплыл» → `hawell_read`: адреса уникальны, инструкции известные.

## Как запускать

Синхронизатор поднимает сервер сам (`sysai-agent mcp haiwell-happy`); вручную — `python server.py`, построчный
JSON-RPC 2.0 в stdin/stdout. Доступы к папкам проверяет SYSAI до вызова.

## Ошибки

- **`нет файла спецификации: …`** — спецификацию делает `plc_spec`; путь с другой машины не откроется.
- **`в спецификации нет механизмов`** — программа была бы пустой: сначала механизмы в спецификации.
- **`адрес не по правилам Haiwell`** / **`адрес … у двух сигналов`** — поправили `io.csv` руками: так нельзя,
  экспорт перезапишет; правьте спецификацию.
- **`это не файл Haiwell Happy`** — нет заголовка `b0 b0 HaiWell`.
- **`файл слишком мал для проекта`** — меньше 1 КБ: скорее всего, скачался огрызок.

## Чего не делать

Не выдавать экспорт за готовый `.gpc` и не подменять формат: «похожий» файл Haiwell откроет пустым. Не
додумывать за инженера датчик скорости и сброс аварии — если их нет в спецификации, инструмент пишет об этом в
замечаниях, и это надо провести по проекту, а не замазать.
